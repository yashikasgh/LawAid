Project Overview & Architecture Summary
What LawAid Does
LawAid is a privacy-first, locally-hosted AI platform that bridges the gap between citizens, police officers, and
legal professionals in understanding and filing FIRs under the new Bharatiya Nyaya Sanhita (BNS). It replaces
confusion around the IPC-to-BNS transition with an intelligent, guided experience.

GitHub Repository Structure & Collaboration Setup
The monorepo is split into three independent top-level directories so each person can work without ever
touching the other's code. Shared contracts (API schemas, environment configs) live in a fourth directory.

Golden Rules for Zero-Conflict Collaboration
• Never commit directly to main. Always open a Pull Request and get one review.
• Each person owns their directory. If you need to touch another person's code, open an issue first.
• Shared schemas in shared/schemas/ — agree on changes in the group chat before modifying.
• Use .env.example (committed) and .env (gitignored). Never commit real secrets.
• Write a one-line commit message: feat(auth): add JWT refresh token endpoint (conventional commits).
• Pull from dev every morning before starting work to stay up to date.
• Use GitHub Issues to assign tasks. Link every PR to its issue.

Feature Implementation Guide with Tech Stack
4.1 User Authentication & RBAC
Tech stack
FastAPI + python-jose (JWT) + bcrypt + PostgreSQL
How to
build
1. Create /auth/register and /auth/login endpoints in FastAPI. 2. On login, issue a JWT with role
claim (citizen / police / lawyer / admin). 3. Create a get_current_user dependency that decodes the
JWT and injects the user. 4. Create a require_role(role) decorator that gates routes by role. 5. Store
users in PostgreSQL: id, email, password_hash, role, created_at.
Files
backend/app/routers/auth.py · backend/app/models/user.py · backend/app/core/security.py
4.2 Complaint Analysis & NER Extraction
Tech stack
spaCy (NER) + Python + FastAPI
How to
build
1. Load spaCy en_core_web_sm or a custom fine-tuned legal NER model. 2. Extract entities:
PERSON, DATE, TIME, GPE (location), ORG from the complaint text. 3. Custom entity labels:
ACCUSED, VICTIM, OFFENCE_TYPE using spaCy's Ruler. 4. Return structured JSON: { victim,
accused, date, location, offence_type, raw_text }.
Files
ai/fir_engine/ner_extractor.py
4.3 BNS Section Retrieval (RAG)
Tech stack
Sentence Transformers (all-MiniLM-L6-v2) + FAISS + LangChain
How to
build
1. Preprocess BNS dataset: each section = { id, number, title, text, penalty }. 2. Embed each section
using SentenceTransformer and store vectors in FAISS index. 3. On query, embed the complaint
text and run FAISS.search(query_vec, top_k=5). 4. Return matched sections with cosine similarity
scores. 5. Wrap in LangChain RetrievalQA chain so Llama 3.1 can cite sections in answers.
Files
ai/rag/embedder.py · ai/rag/retriever.py · ai/rag/bns_index.faiss
4.4 FIR Generation Engine
Tech stack
Llama 3.1 via Ollama + LangChain + Jinja2 templates + ReportLab (PDF)
How to
build
1. Take NER output + retrieved BNS sections as context. 2. Fill a Jinja2 FIR template with extracted
fields. 3. Pass template + BNS context into a LangChain chain with Llama 3.1. 4. LLM fills in
narrative sections and validates legal language. 5. Render final FIR as PDF using ReportLab.
Generate SHA-256 hash of PDF bytes. 6. Store { fir_id, hash, pdf_path, created_by, timestamp } in
MongoDB.
Files
ai/fir_engine/generator.py · backend/app/routers/fir.py · ai/fir_engine/fir_template.j2

4.5 FIR Understanding Engine (OCR → Explanation)
Tech stack
EasyOCR + Tesseract + PyMuPDF + Llama 3.1
How to
build
1. Accept uploaded FIR image or PDF. 2. For PDF: use PyMuPDF to extract text layer; fall back to
EasyOCR if scanned. 3. For image: run EasyOCR to extract text. 4. Run regex patterns to detect
BNS section numbers in extracted text. 5. For each detected section, retrieve full text from FAISS
index. 6. Pass full FIR + sections to Llama 3.1 with prompt: explain this FIR in simple language, list
the citizen's rights, and suggest next steps.
Files
ai/ocr/extractor.py · ai/fir_engine/explainer.py
4.6 Speech-to-Text for Police Module
Tech stack
OpenAI Whisper (local, whisper.cpp) or Vosk (fully offline)
How to
build
1. Frontend records audio using the Web Speech API or MediaRecorder API. 2. Send audio blob to
backend POST /police/transcribe endpoint. 3. Backend passes audio to Whisper model:
whisper.transcribe(audio_path). 4. Return transcript text. Feed into NER extraction pipeline (same
as text input). 5. Whisper supports Hindi, Marathi, and other Indian languages.
Files
ai/speech/transcriber.py · backend/app/routers/police.py
4.7 Unique FIR ID + SHA-256 Authentication
Tech stack
Python hashlib + UUID + PostgreSQL
How to
build
1. After FIR draft is approved by constable, generate UUID4 as FIR ID. 2. Compute SHA-256 of the
final PDF bytes: hashlib.sha256(pdf_bytes).hexdigest(). 3. Store { fir_id, sha256_hash, officer_id,
timestamp, station_code } in PostgreSQL. 4. Print FIR ID and hash on the bottom of every PDF
page. 5. Verification endpoint: POST /fir/verify accepts fir_id + file, recomputes hash, returns
match/mismatch.
Files
backend/app/services/fir_auth.py
4.8 Legal Chat Assistant
Tech stack
LangChain ConversationChain + Llama 3.1 + FastAPI SSE + React
How to
build
1. Each chat session has a session_id stored in MongoDB with message history. 2. Backend uses
LangChain ConversationBufferWindowMemory (last 10 messages). 3. System prompt: You are a
legal assistant for Indian law. Only answer about BNS/legal topics. 4. Inject relevant BNS sections
from RAG into context before each LLM call. 5. Stream response using FastAPI
StreamingResponse with SSE format. 6. Frontend consumes SSE with EventSource API for live
streaming display.
Files
ai/chat/assistant.py · backend/app/routers/chat.py · frontend/components/ChatInterface.tsx

4.9 Duplicate Complaint Detection
Tech stack
Sentence Transformers + cosine similarity + PostgreSQL
How to
build
1. When a new complaint comes in, embed it with Sentence Transformer. 2. Compare against last
30 days of complaint embeddings stored in PostgreSQL (vector column). 3. If cosine similarity >
0.92, flag as potential duplicate. 4. Return { is_duplicate: true, similar_fir_id: '...' } to the police
constable for review. 5. Constable decides whether to proceed or merge.
Files
backend/app/services/duplicate_check.py
4.10 Multilingual Support
Tech stack
IndicTrans2 (AI4Bharat) or Google Translate API (fallback) + i18next (frontend)
How to
build
1. Frontend: use i18next for UI string translations. Ship Hindi + Marathi + English by default. 2. For
user-typed input in regional languages: run through IndicTrans2 → translate to English for NER. 3.
For LLM output: if user's preferred language is set, add instruction to Llama 3.1 prompt: respond in
[language]. 4. Store user language preference in PostgreSQL users table.
Files
frontend/lib/i18n/ · backend/app/services/translation.py

Suggested Improvements to the Existing Plan
The following improvements extend the original PRD/TRD without breaking the existing architecture. Each is
marked with implementation effort.
CITIZEN FLOW
Replace direct FIR generation with guided next-actions
Effort: Low
Already updated in flow redesign. After BNS recommendation, show: nearest police station map, lawyer
contact directory, helpline 112 button, legal aid org finder. Citizens cannot file FIRs themselves — this is legally
accurate.
Downloadable complaint summary PDF
Effort: Low
Let citizens download a PDF of their incident description + recommended BNS sections to carry to the police
station. Builds trust and helps the constable too.
WhatsApp / SMS channel
Effort: Medium
Integrate Twilio WhatsApp API. Citizens send a voice note or text describing the incident. Bot runs the same
NER + BNS pipeline and replies with recommended actions. Reaches users without smartphone apps.
POLICE MODULE
Voice input with multilingual STT
Effort: Medium
Use OpenAI Whisper (local). Supports Hindi, Marathi, Tamil, and 90+ languages. Victim speaks in their
language; transcript is auto-translated to English for NER processing.
BNS sections shown with explanations to constable
Effort: Low
Each suggested section shows: section number, offence name, minimum/maximum penalty, and a 2-line
plain-English explanation. Constable can click to expand full section text.
Constable OTP confirmation before FIR lock
Effort: Low
After draft approval, send OTP to the constable's registered phone. Constable enters OTP to cryptographically
lock the FIR. This adds human authorization on top of the SHA-256 hash.
Victim notification SMS when FIR is registered
Effort: Low
After FIR is locked, send the victim an SMS with FIR ID, station name, and a tracking link. Use Twilio or
Fast2SMS (cheaper for India).
AI & TECHNICAL
Agent layer above Ollama
Effort: Medium

Citizens can check status by FIR ID without visiting the station.
Offline mode for police module
Effort: High
Use a service worker to cache the police module pages. Queue FIR data in IndexedDB. Sync to the server
when connectivity is restored. Critical for rural police stations.

Parallel Collaboration Rules & GitHub Workflow
How to work simultaneously without stepping on each other
The Three-Directory Contract
The most important rule: each person's directory is their kingdom. Person 1 never modifies frontend/. Person 2
never modifies backend/ router files. Person 3 never modifies ai/ model files. The only shared territory is
shared/schemas/ — and changes there require a group chat discussion first.
API Contract First Approach
In Week 1, define all API endpoints as OpenAPI specs in shared/schemas/api.yaml before anyone writes
implementation code. Person 3 can then build the entire frontend against mock API responses using MSW while
Person 1 builds the real endpoints. When Person 1 is done, Person 3 just removes the mocks — no refactoring
needed.

Merge Conflict Prevention
• Keep functions small and in their own files. Large files = more merge conflicts.
• Use index files (index.ts, __init__.py) to re-export — import from the module, not the file.

Environment Setup & Developer Onboarding
How to get from zero to running in one sitting
Prerequisites (All Three People)
• Python 3.11+ (use pyenv for version management)
• Node.js 20+ (use nvm for version management)
• Docker Desktop (or Docker + Docker Compose on Linux)
• Git 2.40+
• Ollama — download from ollama.ai and run: ollama pull llama3.1
• VS Code with extensions: Python, ESLint, Prettier, GitLens, Docker
First-Time Setup
Step
Details
1. Clone repo
git clone https://github.com/your-team/lawaid.git && cd lawaid
2. Copy env file
cp shared/docker/.env.example .env (fill in your values)
3. Start services
docker-compose -f shared/docker/docker-compose.yml up -d (starts PostgreSQL,
MongoDB, Redis)
4. Backend setup
cd backend && python -m venv venv && source venv/bin/activate && pip install -r
requirements.txt && alembic upgrade head
5. AI setup
cd ai && pip install -r requirements.txt && python scripts/build_bns_index.py
6. Frontend setup
cd frontend && npm install && cp .env.local.example .env.local
7. Run all
From root: make dev (or run each service separately in 3 terminals)
8. Verify
Open http://localhost:3000 — you should see the LawAid landing page
Makefile Shortcuts (add to repo root)
make dev # start all services in dev mode
make test # run all tests (pytest + jest)
make lint # run flake8 + eslint
make migrate # run alembic upgrade head
make seed-bns # rebuild BNS vector index
make docker-up # docker-compose up -d
make docker-down # docker-compose down
